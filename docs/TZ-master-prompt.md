# МАСТЕР-ПРОМТ: сайт бетонного завода / РБУ

Используй этот документ как техническое задание и запреты. Сначала заполни бриф. Пока бриф неполный — не выдумывай адреса, ИНН, цены, зоны и юрлицо.

Ниша: B2B/B2C поставка бетона. Посетитель за 3 секунды должен понять: кто, что продаёт, откуда производство, куда доставка, цена, 24/7, как заказать. Дизайн простой и ясный, не агентский «вау».

Режим работы на всех сайтах фиксирован: 24/7. Не уточнять, не дробить на «заявки до 20:00», не подставлять график пн–вс.

────────────────────────────────────
1. ЖЁСТКИЕ ЗАПРЕТЫ (из аудита; нарушение = брак)
────────────────────────────────────

Сеть и гео
- Не клонировать сайт с заменой города. Не делать doorway: «бетон в деревне-1 / деревне-2 / деревне-3».
- Одна страница ≠ завод + главный город + весь район сразу. Главная не конкурирует сама с собой.
- Один населённый пункт — одна основная SEO-страница. Не делать одновременно /dostavka/gorod/ + gorod.site.ru + beton-gorod.ru под один запрос, если контакты и тексты одни.
- Поддомен не по умолчанию. Запрещён копипаст основного сайта на city.site.ru.
- Нельзя фиктивный адрес в городе спроса. Карты / LocalBusiness = реальное предприятие.
- Не писать ИНН/ОГРН, если это свяжет сетку сайтов. Экспертность — годом работы, фото завода, документами качества, объектами.
- Не копировать статьи, FAQ, «фундамент под ключ» и товарные тексты с других доменов сети. Близкие темы и одинаковые даты публикации палят сетку.
- Фотопакет не переносить с соседних сайтов один в один.

Техника и индекс
- Запрещены дубли: www и без www оба 200; / и /index.html оба 200. Нужен 301: http→https, www→основной хост, /index.html и /index.htm → /.
- Внутренние ссылки только на канонические URL. «Главная» = `/`, не index.html.
- Запрещён SPA-каталог: пустой `<div id="root">`, контент только после JS, H1 «Загрузка…», canonical всех URL на главную.
- Title, Description, H1, canonical, цены, основной текст, FAQ и HTML-ссылки на товары — в серверном HTML (SSR/SSG). JS — фильтры, калькулятор, аккордеон.
- Запрещены SEO-категории через `?section= ?cat= ?category= ?g= ?group= ?sub= ?slug= ?service=`. Это UX-фильтры, не посадочные.
- Не вести меню, футер, «все позиции», крошки на параметрический URL, если есть ЧПУ-категория.
- Не каноникалить сотни карточек на `/product.html`.
- Не редиректить главную на `/?service=delivery`. Доставка — отдельный `/dostavka/`.
- Не оставлять `{CITY} {REGION_GEN} {PHONE} {PRICE}` и Lorem ipsum.
- Не анимировать счётчики от 0 в HTML: в исходнике сразу реальные числа.

Контент и факты
- Фактические ошибки важнее орфографии. Противоречие на странице = критический брак.
- М100 и М350 не получают одно «для чего подходит». Применение по марке/классу, согласованное с ГОСТ, не шаблоном.
- Аренда АБН — не шаблон бетона: никаких «мин. объём 1 м³», «стоимость материала», «доставка за м³», «паспорт качества и ТТН» как у смеси.
- Цена «от» в hero = минимальная цена того, что обещает заголовок (не ЦПС, если страница про товарный бетон).
- Visible price = таблица = JSON-LD Offer.price — один источник. Не `price: "200"` при цене 2820.
- НДС, срок подачи, мин. объём — одинаковы во всех блоках, шапке, футере, контактах, schema.
- Режим только 24/7. Запрещены любые другие часы: «пн–вс 08:00–18:00», «до 20:00», «09:00–23:00», «в рабочие часы», «срочная доставка по согласованию вместо 24/7». Если в макете/данных пришёл другой график — заменить на 24/7, не оставлять оба.
- Не вшивать год в Description («актуально на 2024»), если нет автообновления.
- Не ставить рейтинг магазина / чужие отзывы. Self-serving AggregateRating звёзд в Google не даст — не обещать.
- Кнопка «Связаться» и аналоги — всегда `tel:` / форма / мессенджер, никогда якорь на другой блок.
- Слово «каталог» в UI везде заменить на «цены» / «прайс-лист». URL `/catalog/` допустим.

────────────────────────────────────
2. ГЕОАРХИТЕКТУРА (критично)
────────────────────────────────────

Стратегия: не десятки шаблонных доменов и не одна страница «на всю область».
Один официальный ресурс + региональные сайты под реальные заводы + точечные геопосадочные/поддомены только там, где есть спрос, логистика и уникальный контент.

Иерархия
1. Главная = завод / основное производство / основной бренд-локал.
   Title/H1/Description бьют в ЭТОТ локал, не в «Москва и МО» и не в «СПб + Ленобласть», если завод в Долгопрудном / Вистино / Фёдоровском.
   Широкая география — отдельными страницами, не размытием главной.
2. Крупный город спроса = 1 сильная геопосадочная на том же домене:
   `/kingisepp/`, `/ust-luga/`, `/tosno/`
3. Район / зона = `/dostavka/` с Title/H1 про район, внутри список зон со ссылками на города.
4. Мелкие НП — только при спросе и уникальных условиях доставки:
   `/dostavka/{np}/` (расстояние, время, тариф, маршрут, объёмы). Не массово.

Поддомен `city.site.ru` — только если ВСЕ пункты истинны:
- город ключевой по спросу;
- реально другой контент: зона, сроки, тексты, FAQ, расчёт доставки;
- перелинковка с основным сайтом;
- локация в Яндекс Вебмастере;
- (для Яндекса желательно физическое присутствие; без него поддомен — осознанный риск).
Иначе — посадочная на основном домене.

Правило решения
- Большой спрос + своя логистика + хватает контента → поддомен (или сильная посадочная, если поддомен дорог).
- Небольшой спрос → посадочная.
- Посёлок у крупного города → страница внутри его направления.
- Посёлок у завода → страница на сайте завода.
- Нет уверенности → сначала посадочная, не поддомен.

Приоритет работ на новом сайте
1) Главная = завод / основной локал
2) `/dostavka/` (Title/H1 + зоны)
3) 1–2 сильные геопосадочные под главные города
4) Перелинковка
5) ЧПУ-разделы прайса
6) Остальные НП — только по спросу
7) Под основные марки со спросом — карточки, не 200+ тонких SKU

На каждой геопосадочной обязательно
- Title: «Купить бетон в {Город} с доставкой — цена за м³»
- H1: «Бетон в {Город}е с доставкой»
- цены и стоимость доставки именно до этого города
- время подачи миксера
- АБН (если есть)
- минимальный объём
- FAQ про доставку в этот город
- честно: производство в {Завод}, доставляем в {Город}
- режим 24/7 (в тексте и FAQ, не «доставка в рабочие часы»)
Страница полезнее абзаца «купить бетон в {Город}е недорого».

Страница доставки
- Title/H1: «Доставка бетона по {Район}у — цены и зоны», не «Доставка бетона — Компания».
- Список зон → геопосадочные городов.
- Базовый тариф / простой / мин. объём — что можно сказать честно. Нет точного расчёта — написать от чего зависит, не выдумывать.

Перелинковка (после появления геостраниц)
- С главной — заметная контекстная ссылка на города / доставку.
- Со страницы доставки — на геопосадочные.
- С карточек: «Доставка М300: {Завод}, {Город1}, {Город2} и {Район}» — города ведут на геостраницы.
- Крошки товара: Главная → {Категория} → {Товар}, не Главная → Прайс → Товар в обход категории.

Карты
- Одной SEO-страницей нельзя гарантированно перебить конкурента с адресом в самом городе.
- Органика формата «Бетон в {Городе} с доставкой из {Завода}» — нормальная рабочая модель.
- NAP + режим: сайт = Яндекс Бизнес = карты = футер = 24/7. На картах тоже круглосуточно, не оставлять 09:00–18:00 в карточке организации.

────────────────────────────────────
3. ИНФОРМАЦИОННАЯ АРХИТЕКТУРА И URL
────────────────────────────────────

Индексируемые узлы — ЧПУ, латиница, дефисы, свой Title, Description, H1, self-canonical, контент.

Обязательный каркас
- `/` — главная (завод)
- `/price/` или `/catalog/` — полный прайс одним списком (оставить, это удобно)
- `/catalog/tovarnyy-beton/`
- `/catalog/beton-s-pmd/`
- `/catalog/beton-na-granite/` (если продаём)
- `/catalog/beton-na-gravii/`
- `/catalog/rastvory/`
- `/catalog/arenda-abn/` (или `/arenda-avtobetononasosa/`)
- `/dostavka/`
- `/dostavka/{gorod}/` или `/{gorod}/` — только приоритетные
- `/contacts/`
- `/about/` — с какого года, где завод, чем подтверждаем качество
- Политика конфиденциальности + согласие на ПДн в футере, если есть форма

Подкатегории — тоже ЧПУ, не `?sub=`
- `/catalog/beton/tovarnyy-beton/`
- `/catalog/beton/na-granite/`
- `/catalog/beton-s-pmd/pmd-10/`

Марки — отдельные URL только при спросе
- `/catalog/tovarnyy-beton/m300/`
- Не плодить все комбинации B/F/W/П из прайса. Тонкая карточка без применения, доставки и отличия от соседней марки — не создавать или noindex.

Услуги «по назначению» (если есть спрос): бетон для фундамента / перекрытий / монолита — отдельные посадочные с марками и ценами, не якоря на общий `/beton.html`.

Фильтры `?category=` можно оставить для UX, но:
- 301 или canonical на ЧПУ-категорию;
- меню и футер не ссылаются на фильтр.

Хлебные крошки HTML + BreadcrumbList совпадают.

Sitemap: только канонические 200 indexable URL. Не включать `?cat=`, www-дубли, index.html.
robots.txt не закрывает прайс, марки, доставку.

────────────────────────────────────
4. ТИПЫ СТРАНИЦ: ЧТО ДОЛЖНО БЫТЬ
────────────────────────────────────

Главная
- Hero: реальное фото ЭТОГО завода (не сток). В H1 — коммерческие ключи из брифа.
- Сразу: кто / откуда / куда / цена от (правдивая) / 24/7 / как заказать.
- 24/7 в шапке, hero, оффере, контактах, футере. Не прятать только в Title.
- После hero — сворачиваемая таблица прайса по бетону.
- Не дублировать «цены» и «прайс-лист» двумя одинаковыми блоками.
- Блок заводов/доставки со ссылками на геостраницы (не простыня из 200 деревень и метро).
- Форма: телефон, объём, адрес доставки, кнопка «Получить расчёт» + tel + мессенджер.
- Доверие: год работы, фото БСУ/техники/объектов, документы качества (реальные), свежие отзывы если есть.

Категория (товарный бетон, ПМД, растворы…)
- Свой шаблон под интент. Не универсальный «материал + доставка за м³» на аренду и песок.
- H1 с гео завода: «Бетон с завода в {Завод}», не голое «Бетон» и не «по Москве и области».
- Таблица позиций, цены с датой актуальности, применение категории, FAQ, перелинковка на марки и доставку.
- Не пытаться одной страницей ранжироваться за все группы сразу.

Карточка марки
- Уникальное применение под марку/класс (ГОСТ / отраслевой смысл).
- Характеристики B / M / F / W / П согласованы внутри страницы и с соседними страницами (М500 ≠ то B35, то B40).
- Цена, НДС, мин. объём, подача, ссылки на геодоставку.
- FAQ по этой марке, не копипаст соседней.
- Отличие от соседних марок (зачем М300, а не М250).

Аренда техники — ОТДЕЛЬНЫЙ шаблон
- Вылет, производительность, смена/час, простой, диаметр бетоновода, требования к площадке, зона работы.
- Нет бетонных характеристик «марка/класс/м³».

Статьи (если раздел есть)
- Либо живой раздел: не чаще пачки в один день, ориентир 1 материал в 2–4 недели, факты проверены, гео этого завода.
- Либо удалить. Мёртвый блог / статьи 2023 на домене 2026 = сигнал «заброшен» (Diligence Bad).
- Не переносить тексты с гео другого региона.

────────────────────────────────────
5. ТЕКСТ, SEO, ДОСТОВЕРНОСТЬ
────────────────────────────────────

- Не пиши лозунги компаний. Краткое SEO, особенно в заголовках. Один H1. Иерархия H1 → H2 → H3, не прыжок в H3.
- Title ~ до обрезки в выдаче, ключ в начале, бренд в конце. «24/7» входит в Title и Description главной (как коммерческий ключ), и тот же режим повторяется в видимых блоках — без второго графика рядом.
- Description уникален, без вшитого года.
- Ключи в первых 100 словах естественно.
- Честно: где производство, куда доставляете.
- Юридические и кадровые факты согласованы: один директор, одно действующее юрлицо, битые ссылки на ликвидированные компании — убрать.
- Режим работы — везде 24/7, одна формулировка:
  шапка, hero, H1/оффер, контакты, футер, FAQ, Open Graph, Twitter, LocalBusiness/OpeningHoursSpecification, подсказки калькулятора.
  Формулировки: «Работаем 24/7», «Приём заявок, производство, отгрузка и доставка — круглосуточно, 24/7».
  Schema: `openingHours: "Mo-Su 00:00-23:59"` (или эквивалент 24/7). Не ставить `08:00–18:00` в JSON-LD, если на сайте 24/7.
- Лаборатория: не писать, что кубики текущей партии испытывают на проектную прочность перед отгрузкой.
  Можно: контроль состава и подвижности перед отгрузкой; образцы испытываются в установленном возрасте; партия с документами о качестве.
- Цены: «актуально на {дата}» / «прайс действителен с …». Можно автоподставлять 1-е число месяца.
- В экспертных абзацах желательны источники (ГОСТ, не выдуманные цифры).
- Отзывы: только про эту компанию; лучше ссылка на Яндекс. Не ежедневная накрутка. Старые 2019 без свежих — не ставить первыми.
- Соцсети в футере — только живые. Битые / чужой регион / Instagram если не ведёте — убрать.

Микроразметка
- Organization и LocalBusiness: стабильные `@id` (`/#organization`, `/#localbusiness`) и `url` = главная, не URL текущей карточки.
- address = реальный завод. Город спроса = `areaServed`, не подмена addressLocality.
- OpeningHours / openingHoursSpecification только 24/7 (`Mo-Su 00:00-23:59`). Запрещён другой график в schema.
- Товар: Product + Offer (цена, currency, availability) на карточке, не на категории со списком 40 позиций.
- Категория: не выдавать Product за группу. При необходимости ItemList / OfferCatalog с реальными offers, либо без пустой оболочки.
- BreadcrumbList обязателен и совпадает с видимыми крошками.
- FAQPage можно оставить, на коммерции rich results почти не будет — это не цель.
- Не ждать звёзд от AggregateRating самой компании на своём сайте.

────────────────────────────────────
6. КОНВЕРСИЯ И UX
────────────────────────────────────

- За 3 секунды: что, откуда, цена, телефон, 24/7.
- CTA в шапке, hero и после прайса. Все рабочие.
- Форма на главной, категориях и карточках. Конфигуратор без отправки заявки — недостаточно.
- Калькулятор не перекрывает контент (баг функциональности бьёт по ранжированию).
- Клик по товару: либо страница, либо превью с кнопкой «открыть». Не flash modal → переход → Back с открытым modal.
- Галерея: лайтбокс на сайте, не скачивание файла в новой вкладке «как папка».
- Навигация сквозная: меню не теряет пункты в разделе статей.
- Счётчики опыта: реальное число в HTML.
- Услуги «под ключ»: что входит, что нет (доставка отдельно — писать у цены).

────────────────────────────────────
7. ДИЗАЙН
────────────────────────────────────

Ниша не любит вычурность. Светлый, понятный, строительный.

Шрифты — выбрать ОДНУ пару, не смешивать больше двух:
- Montserrat — заголовки, Open Sans — текст
- Roboto Bold — заголовки, Roboto Regular — текст
- Oswald — заголовки, Inter — текст
Цены / марки / м³ — полужирным или акцентом.

Размеры ориентир ±3 px
- h1: 32–48 px (кроме hero)
- h2 / h3: 20–30 px
- цены и характеристики: ~16 px, читаемые

Цвет
- Избегать чёрных полотен.
- Земля / стройка: белый, синий, коричневые оттенки. Можно тёмная шапка + светлые секции, без «тёмный SaaS».
- Максимум реальных фото. Hero = фото этого завода.

Адаптив
- Мобилка и iPhone: шапка не наезжает, лого и телефон переносятся, таблица прайса скроллится/сворачивается, CTA доступен большим пальцем, нет горизонтального скролла, тап-зоны достаточные.

────────────────────────────────────
8. РАЗДЕЛЕНИЕ РАБОТЫ МЕЖДУ АГЕНТАМИ
────────────────────────────────────

Агент A — Архитектор
Бриф, карта URL, кто за что ранжируется, список ЧПУ, что не создавать, схема перелинковки, редиректы.

Агент B — Контент и факты
Тексты по типам страниц, ГОСТ-применение марок, FAQ, цены, геочестность. Режим везде 24/7. Сверка противоречий. Без копипаста с других доменов.

Агент C — Вёрстка и UI
Главная, прайс-аккордеон, категории, карточки, аренда, доставка, формы, мобилка. Дизайн-ограничения раздела 7.

Агент D — ТехSEO
301, canonical, SSR мета и контента, sitemap, schema, крошки, абсолютные внутренние ссылки на канон, Organization @id.
OpeningHours везде 24/7, согласован с видимым текстом.

Агент E — Приёмка
Пять проходов ниже. Не сдавать, пока есть красные пункты.

Агенты не имеют права «закрыть задачу», оставив параметрический каталог, JS-H1 или шаблон аренды от бетона.

────────────────────────────────────
9. ПЯТЬ ПРОХОДОВ ПРИЁМКИ + ХОЛОДНЫЙ ВЗГЛЯД
────────────────────────────────────

Проход 1 — Гео и каннибализация
Главная бьёт в один локал. Нет страницы, которая одновременно завод+город+район. Геостраницы уникальны данными. Поддоменов-клонов нет. Адрес реальный.

Проход 2 — Техника индексации
curl без JS: у каждой индексируемой страницы свой Title, Description, H1, canonical, текст, цена, ссылки.
301 www / index.html. Нет ссылок на index.html и `?category=` в меню.
Sitemap = канон. Schema: цена = видимая, Organization url = главная, адрес завода правдивый, openingHours = 24/7.

Проход 3 — Факты
Прайс vs hero vs JSON-LD. НДС. Режим: на сайте нет ни одного графика кроме 24/7 (шапка, контакты, FAQ, калькулятор, schema). Марка↔класс. Применение М100 ≠ М350. Аренда без бетонного FAQ. Директор/реквизиты/соцсети. Лабораторные формулировки. Дата цен. Нет {PLACEHOLDER} и Lorem.

Проход 4 — Вёрстка и композиция
Иерархия, сетка, прайс после hero, нет двух одинаковых прайсов, калькулятор не ломает layout, галерея, сквозное меню.

Проход 5 — Мобилка / iPhone
320–430 px: шапка, hero, аккордеон прайса, форма, tel, таблицы, тап по CTA. Нет горизонтального скролла.

Холодный взгляд 30 секунд (обязательно перед сдачей)
Зацепило ли? Сразу ясно: кто / что / откуда / куда доставка / цена / 24/7 / как заказать?
Если нет — править hero и шапку, не добавлять секций.

────────────────────────────────────
10. КРИТЕРИЙ ГОТОВНОСТИ
────────────────────────────────────

Сайт можно сдавать, только если:
- бриф не нарушен выдуманными фактами;
- главная не размыта широкой географией;
- категории и приоритетные марки — ЧПУ + SSR;
- аренда и бетон — разные шаблоны;
- контакты и режим 24/7 совпадают везде (текст + schema, без второго графика);
- цены с датой актуальности и одним источником;
- форма и телефон работают;
- пять проходов без красных замечаний;
- холодный взгляд: заказ бетона понятен за 30 секунд, 24/7 видно сразу.

Если данных не хватает — спроси. Не заполняй пробелы вымыслом: фиктивный адрес, чужой город, липовые отзывы, сток-завод. Режим не спрашивать и не менять: всегда 24/7.
